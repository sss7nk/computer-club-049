# Компьютерный клуб 049

Курсовой проект Добрынина Даниила Александровича, группа ИСП-049.
Тема: «Проектирование и разработка информационной системы для автоматизации учета и бронирования рабочих мест компьютерного клуба».

Сайт включает публичную страницу клуба и кабинеты сотрудников. Данные сохраняются в SQLite, регистрация и проверка прав выполняются сервером.

Опубликованный сайт: https://computer-club-049.computer-club-isp049.workers.dev/

## Запуск

Нужен Node.js **24 или новее**. Из папки сайта:

```sh
npm ci
npm start
```

Открыть http://127.0.0.1:4173. В Windows также можно запустить `Запустить.ps1` после установки зависимостей. При первом запуске создаётся `.runtime/club.sqlite` с учебными данными. Повторный запуск сохраняет изменения.

## Учётные записи

Общий учебный пароль: `Club_Demo_2026!`.

- `manager` — управляющий: сотрудники, назначение ролей, справочники, тарифы, все отчёты и CSV.
- `admin` и `admin2` — администраторы: клиенты, бронирования, переносы, отмены, неявки, запуск, продление и завершение посещений.
- `cashier` — кассир: завершённые сеансы, однократная полная оплата, просмотр выручки.
- `technician` — техник: неисправности, блокировка мест и подтверждение ремонта.
- `accountant` — бухгалтер: финансовый отчёт и выгрузка выручки в CSV.

Нового сотрудника регистрирует управляющий в разделе «Сотрудники». Можно назначить несколько ролей. Изменение ролей или отключение записи отзывает текущий вход сотрудника. Клиенты учитываются как посетители; самостоятельная онлайн-регистрация клиента в текущем ТЗ не предусмотрена.

## Основные правила

Бронирования используют интервалы `[начало, конец)`: соседние интервалы допустимы, пересечения запрещены. Запуск по брони возможен от начала до срока ожидания: минимум из «начало + 15 минут» и конца брони; на самой границе уже фиксируется неявка. Посещение без брони возможно на свободном исправном месте.

Ставка копируется в сеанс при запуске. Расчёт: минуты округляются вверх, стоимость равна `ставка × минуты / 60`, результат округляется до копеек по правилу HALF_UP. При продлении сохраняется ставка, проверяются следующие брони. Новые цены создаются новой версией тарифа.

Техник регистрирует фактическое время поломки: место блокируется, затронутые неначатые брони требуют переноса или отмены. Уже идущий сеанс завершает администратор; время после остановки не начисляется. Кассир сохраняет оплату после получения всей суммы. Повторная оплата запрещена.

## Структура

- `public/` — HTML, CSS, клиентские ES-модули; SVG игрового места хранится в исходном коде.
- `server/` — API, роли, расчёт стоимости, отчёты, пароли, локальный HTTP-сервер и SQLite-адаптер.
- `db/` — предметная схема, служебные таблицы сайта и учебные данные.
- `drizzle/` — последовательные миграции для Cloudflare D1.
- `worker/` — серверная точка входа для Cloudflare Workers.
- `scripts/` — сборка, проверка и резервное копирование.
- `tests/` — сценарии API и дополнительные браузерные проверки.
- `docs/` — связь реализации с требованиями и инструкция размещения.

Клиентская часть разделена на модули состояния, API, DOM, форматирования, элементов интерфейса, навигации, публичных страниц, страниц сотрудников, темы и SVG-иллюстрации. DOM используется для форм, событий, диалогов и сообщений; BOM — для маршрутов через `location`, истории браузера, сохранения темы в `localStorage`, системной темы `matchMedia` и события `storage` между вкладками. Авторизация в localStorage не хранится.

Доступны светлая и тёмная темы с учётом системного предпочтения и сохранением ручного выбора. Интерфейс адаптируется под мобильный экран; широкие таблицы прокручиваются внутри своего блока.

## Публикация в Cloudflare

Сайт размещается в аккаунте владельца на Cloudflare Workers, база — в D1. Адрес публикации имеет домен `workers.dev` либо подключённый собственный домен.

После `npm ci`:

```sh
npm run cloudflare:login
npm run cloudflare:setup
npm run deploy
```

Первая команда открывает вход Cloudflare. Вторая создаёт или находит базу `computer-club-049-db` и записывает её настоящий идентификатор в `wrangler.json`. Третья применяет новые миграции, загружает учебные данные только в пустую базу и публикует сборку. Повторная публикация не очищает данные. Полученный URL показывает Wrangler.

Ключи доступа в проект не копируются: вход обслуживает Wrangler. Проверка сборки без публикации: `npm run deploy:check`. Данные и настройки локального Wrangler исключены из Git и ZIP.

## Проверки и копии

```sh
npm test
npm run build
npm run db:check
npm run db:backup
```

Восстановление при остановленном сервере: `node scripts/database.mjs restore путь_к_копии.sqlite`. Перед заменой проверяется целостность, предыдущий файл сохраняется, старые входы отзываются.

Браузерные проверки запускаются отдельно после установки Playwright и Microsoft Edge: `node tests/browser-check.cjs` и `node tests/theme-browser.cjs`. По умолчанию они используют отдельный сервер на порту 4174. Основные тесты `npm test` не требуют браузера и используют базы в памяти.

Схема содержит 14 предметных таблиц, `meta` и четыре технические таблицы веб-приложения. Файл из комплекта «База данных» — отдельный учебный снимок. Сайт создаёт собственную рабочую базу; при подготовке его наполнения исторические сеансы закрыты, даты сдвинуты назад, чтобы снимок не оказался в будущем. Импорт произвольного SQLite-файла вместо рабочей базы не предусмотрен.

Учебные данные вымышлены. Сайт не списывает деньги с банковской карты и не управляет питанием компьютеров: сотрудник фиксирует совершённые действия клуба.
