# Размещение и обслуживание

Облачная публикация выполняется напрямую в аккаунт владельца Cloudflare. В проекте используется Wrangler с конфигурацией `wrangler.json`. Последовательность после `npm ci`: `npm run cloudflare:login`, `npm run cloudflare:setup`, `npm run deploy`. Команда настройки находит или создаёт `computer-club-049-db` и сохраняет полученный от Cloudflare идентификатор; выдуманные идентификаторы не используются. Команда публикации применяет ожидающие миграции до загрузки Worker.

Wrangler печатает фактический адрес вида `workers.dev`. Его нужно сохранить для демонстрации преподавателю. Пока вход в аккаунт и публикация не завершены, новый адрес не считается готовым. `npm run deploy:check` только проверяет сборку, не загружая сайт и не создавая облачные ресурсы.

Для локального запуска нужны Node.js 24 и SQLite: `npm ci`, затем `npm start`. Сервер слушает локальный адрес. Переменные `PORT` и `CLUB_DATABASE` задают порт и отдельный путь к SQLite. Каталог `.runtime` содержит рабочие данные и исключён из репозитория и сдаваемого ZIP.

`npm run build` собирает браузерные модули в `dist/client/app.js` и Cloudflare Worker в `dist/server/index.js`. Редактировать следует исходники. Служебные файлы провайдера публикации не входят в учебный комплект.

Для Cloudflare Workers нужна привязка D1 с именем `DB`. В новую базу последовательно применяются `drizzle/0000_course.sql` и `drizzle/0001_web.sql`. Применённые миграции не переписываются. При прямом размещении Wrangler загружает `db/seed.sql` до публикации, только если в meta отсутствует снимок. Это позволяет выполнить начальное заполнение вне лимита запросов отдельного HTTP-вызова. Повторная публикация не очищает базу. Резервный механизм первого заполнения API сохранён для локального запуска. Таблицы не создаются внутри HTTP-запросов.

Миграции содержат только структуру. Новые миграции добавляются следующими файлами с обновлением журнала. Локальная SQLite и облачная D1 — разные рабочие базы; изменения не синхронизируются автоматически.

Резервная копия SQLite: `npm run db:backup`. JSON-снимок предметных данных доступен управляющему в разделе сотрудников; он не заменяет полный SQLite-файл с техническими таблицами. Восстановление выполняется при остановленном сервере. Доступы к облачной платформе в проекте не хранятся.

Для демонстрации преподавателю нужен доступный ему опубликованный сайт. Адрес 127.0.0.1 работает только на компьютере с запущенным сервером; репозиторий GitHub сам по себе сайт не запускает.
