# Публикация на Bothost

Сайт запускается как обычное приложение Node.js 24 с SQLite. Соединения с Cloudflare и Sites для этой публикации не нужны. Используется тот же API и тот же набор правил. Это отдельная рабочая база: записи двух публикаций автоматически не синхронизируются.

В аккаунте Bothost выберите бесплатный Starter и создайте приложение из репозитория https://github.com/sss7nk/computer-club-049. Включите собственный Dockerfile, основной файл `server/local.mjs`, домен и внутренний порт 3000. Автоматическую HTTP-обёртку включать не требуется: HTTP-сервер уже реализован в приложении.

Dockerfile устанавливает Node.js 24 и только зависимости запуска. Сборка интерфейса для этого варианта не нужна: браузер получает ES-модули из public. Переменная PORT задаёт порт; LISTEN_HOST=0.0.0.0 позволяет прокси подключиться к контейнеру.

Bothost передаёт DOMAIN — фактический домен приложения. Сервер использует его для проверки Host и Origin и выставляет Secure-cookie при HTTPS. При необходимости адрес задаётся явно через PUBLIC_ORIGIN, например `https://адрес-из-панели`. Доверие к произвольным заголовкам X-Forwarded-Host или X-Forwarded-Proto не включается.

База сохраняется в `/app/data/club.sqlite`; Dockerfile задаёт DATA_DIR=/app/data. По документации Bothost, этот каталог является постоянным томом и сохраняется между пересборками. Не переносите рабочую базу в корень репозитория. При первом запуске создаются схема и учебные данные; повторный запуск сохраняет изменения.

После размещения проверить: `/health`, главную страницу, вход пяти ролей, регистрацию нового сотрудника и сохранность записи после перезапуска. Реальную ссылку для преподавателя можно считать готовой после этой проверки. Доступность из сети проверяющего уточняется отдельно — наличие домена .ru само по себе её не гарантирует.

Проверка SQLite внутри контейнера: `node scripts/database.mjs check`. Резервная копия: `node scripts/database.mjs backup`; копии по умолчанию сохраняются в `/app/data/backups`.
